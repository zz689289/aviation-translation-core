# Publication lifecycle

Read dual_agent_workflow.md, evidence_contract.md, docx_layout_policy.md and qa_policy.md. Current artifact identity comes from path, hash and applicable decisions, never the latest-looking filename or an old project status.

1. Inspect and lock English source, approved terms/assets and project structure. Initialize a source-derived layout specification. Record source page count and expected content layers, not another project's counts. A renderer problem blocks its render/release stage, not translation or offline DOCX construction.
2. Executor translates/builds; one independent QA inventories the original source and compares all content layers to a stable candidate. Stage batches if needed, recording actual coverage. Build true fields, tables, footnotes, formulas and a source-derived TOC whitelist.
3. Run docx_preflight.py before Word and on the actual saved result. Batch clear-source repairs automatically. During iteration use one effective Word render and actual affected/adjacent-page review, broadening for repagination or global changes. Do not run the final double-render gate after every edit. Source-semantic ambiguities go to one consolidated manual handoff, not a whole-document retranslation.
4. Reuse the project's verified export runtime by path/version/hash and an applicable versioned profile. See word_execution.md. Never reintroduce an old broken renderer or old manual-only requirement after a supported, authorized route has succeeded. A capability PASS is not document acceptance.
5. Plan metadata treatment before final acceptance. Finish internal fields/whole TOC, pagination and actual save. Close/reopen the saved DOCX; compare its TOC caches to the exported PDF/body pages. Then, if scrub is required, create a new sanitized final copy using a declared property/comment-part allowlist; verify all layout/content members unchanged. Do not remove comments/relationships outside that authorization. Never mutate an accepted artifact.
6. Freeze the final artifact. Perform two independent Word exports from fresh copies of the same final source with a declared invocation/profile; final read-only validation must not update/save after a metadata-only scrub. If that Word profile needs saving, declare it before freeze and finish artifact preparation before final acceptance. Avoid repeated scrub/reopen/save loops.
7. Check final actual pages completely (new evidence or valid page-specific reuse), source coverage, package, tables/captions/figures/formulas/notes, saved caches, branding, page fields and determinism. Pixel equality proves repeatability, not semantic correctness. Differences require classification; no binary-PDF-hash gate or generic automatic tolerance. Exact scoped human acceptance can dispose of specific nonsemantic differences without authorizing future ones.
8. Human proofreading acceptance, technical suggestion disposition and formal release are distinct states. Final release requires exact-artifact evidence and explicit applicable release authority. Copy/rename does not invalidate content-hash evidence but staging readback must verify identity. New artifact/dependency changes invalidate relevant evidence. Do not run anything merely because a session changed.

The bundled build/render scripts are optional generic tools, not mandatory replacements for a verified project pipeline. Preserve validated controls, fail closed when an adapter cannot represent a required structure, and report that limit rather than silently flattening it.

For this user's Windows Word automation, route new exports through [word_export_tool.md](word_export_tool.md); historical click-No runs are evidence only. This changes tool invocation, not document release/dual-render/visual gates.
