# Machine evidence contract (workflow schema 1.2)

`workflow.py` is a deterministic gate/helper, NOT a translator, visual assessor, independent agent simulator or Word runner. A human/model must supply actual semantic and visual observations; scripts cannot manufacture them.

Commands: `snapshot`, `verify-snapshot`, `route`, `cache`, `coverage`, `scope`, `plan`. Each takes `--spec <json> --output <new-json>` (verify-snapshot reads the saved snapshot). Exit 0 = requested mechanical gate PASS; 1 = real unfinished/failed gate; 2 = invalid input. No overwrites. Schemas validate structure; semantic checks validate content. An empty queue does not mean a complete translation or publication PASS.

Snapshot specification: `artifacts` list of `{id, role, path, expected_sha256?}`; `dependencies` contains source, target, assets, style, checker, render environment fingerprints. Output has the observed size/hash for each named artifact and a canonical identity excluding filenames/timestamps. Bind the real child ID to this identity. Protected files are checked at intake, relevant write boundaries and final staging, not recursively for every paragraph.

Routing specification: `findings` list with ID, status (`PENDING`, `OPEN`, `RESOLVED`), root_cause, scope, source_evidence, repair_evidence, semantic_uncertainty, source_editorial_change, approved_term_change, new_permission and optional repair_history. OPEN without evidence cannot be auto-fixed. Unchanged failed attempts twice require root-cause diagnosis. Routine repair never becomes a published PASS merely by routing; revalidation is explicit.

RESOLVED also requires all four decision flags, valid source evidence, target_sha256 and a `recheck_record` path+SHA. That JSON must bind finding_id, `context_sha256=workflow.finding_binding(finding)`, target_sha256 and status=PASS. The context digest includes target_sha256: a new target needs a new applicable decision, not merely a new recheck. A true decision flag needs its own `decision_records[flag]` path+SHA JSON, binding the same finding/context and decision_flag. Human decisions use authority=CURRENT_USER_EXPLICIT_DECISION, status=HUMAN_APPROVED and explicit human_decision_approved=true; new_permission uses actual PLATFORM_TOOL_PERMISSION/GRANTED evidence and permission_granted=true. An executor-written recheck is not an approval. The checker verifies declared bindings, not identity/authenticity; only actual user/tool events can populate authority evidence, and platform permission enforcement still applies. Modified scopes invalidate old approvals.

Cache specification: `record` and `current`. Only complete PASS records with matching scoped dependency fingerprints, exact scope IDs and intact evidence may be reused. Source/target/assets/style/checker/environment fingerprints are scoped to the check, not a recursive hash of a project. Rules and applicable decisions belong in the style/checker inputs and the review criteria. Changing the underlying requirement invalidates the relevant check even when the pixels remain equal.

For `visual_page`, both sides additionally name `artifact_sha256` (whole PDF) and `review_contract={criteria:{path,sha256}, aspects:[...], method, source_compared}`. The criteria file is immutable and identical across reuse. The old record must cover all current aspects and have method `READABLE_PAGES_AND_DETAIL`; `source_style` additionally needs source_compared=true. Contact sheets or readability alone cannot prove source-style coverage. `record.revoked=true` or `current.invalidated_aspects` intersecting required aspects blocks reuse. Keep the failed historical report; only a new applicable review can close the gap.

Current visual reuse needs actual_render_comparison_pass=true, comparison_evidence, and comparison_record (path+SHA). That JSON binds baseline_target_sha256, candidate_target_sha256, exact scope_ids, dimensions_equal=true, raw_text_equal=true and decoded_pixels_equal=true. Use actual unnormalized text and decoded pixels. Whole PDFs may differ outside this scope; the scoped dependency hashes must remain equal. New semantic/style content inside this scope cannot reuse the old review. A comparator declaration cannot authenticate a person's observation; retain the actual reviewer/tool evidence. Legacy pixel-only records must be supplemented or repeated at their missing scope, never silently promoted.

`plan` consumes task (excerpt/translate/repair/qa/resume), and for document tasks output_format (pdf/docx/text) and document_kind (paper/manual/other). It lists references and next checks, never declares task completion. Use the result within the existing state mechanism, not a second project ledger.

Coverage specification: `source_inventory` produced independently from original source, `executor_inventory`, `reviews`, source pages and layers examined (including evidence for absent layers), executor/QA actual distinct thread IDs, snapshot identity and review evidence references. Reconcile sets, not just counts. Duplicate source-ID consumption is illegal except explicit representation mappings (continuation headers can alias one semantic cell; distinct anchors may have identical bodies). Full source audit requires every source unit accounted for and independently reviewed; extra executor-only units need disposition, never disappear. Page review coverage similarly declares all actual final pages with new/reused proof, not source page-count equality.

Supply the complete live `snapshot` output, matching snapshot_id and source_inventory_snapshot_id. Each executor unit binds target_artifact_id and its observed target_sha256; each review binds snapshot_id, target_sha256 and qa_thread_id. `dispatch_record` points to hash-verified JSON recording both actual thread IDs, this snapshot_id and source_first=true; dispatch_evidence preserves actual tool provenance. Evidence from a different target/snapshot cannot PASS. Optional per-review `reuse` must pass the cache gate and match the current dependency set and that one source-unit scope. A record cannot authenticate its own assertion of independent work; retain real dispatch output and source-first QA report for audit. Test fixtures explicitly label synthetic provenance.

Repair impacts: local-text -> changed objects + context/reference/term dependents; local-format -> changed render pages and neighbors; global font/margins/numbering/sections/render environment -> full impacted pages. Actual diff outside the expected scope broadens review or records an unauthorized change; it is never hidden. A changed checker invalidates its affected evidence, not every unrelated check. Use one shared versioned mechanical result per stage and let QA inspect its suitability.

Missing impact data is invalid, not empty PASS: text requires changed_objects, format requires changed_objects/pages, checker requires affected_checks, metadata requires changed_parts and package_diff_evidence. Object-only changes are DISCOVER_AFTER_RENDER, not completed page QA. Checker-only changes rerun named checks without an unrelated Word call. Table invariants require a nonempty render_cell_inventory and nonnull source-coordinate mappings to its real IDs; only recorded repeated-header aliases may share a destination.
