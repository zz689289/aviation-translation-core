# Preparing private inputs manually

Start with the [offline demo](quickstart.md) to understand the shape of the files, then read the [full contract](input_contract.md). The demo authors its own synthetic registries. There is no general PDF-to-registry importer, automatic translation command or automated authority/independence certification.

1. Use a new private root and authorized source/target material. Inspect source pages and all nine document layers yourself. Keep unsupported layers unresolved; never declare them absent merely because extraction omitted them. Only the supported text-PDF contract can be mechanically mapped.
2. Prepare the [source registry](../schemas/source.schema.json) independently from the target: contract_version 2, source/PDF evidence hash, source unit IDs, page, layer, exact text, and complete expected arrays for numbers, units, identifiers, symbols and markers. Expectations must reflect the English source, not values copied from proposed Chinese observations. The schema checks consistency, not actual independent authorship.
3. Prepare the [target registry](../schemas/target.schema.json) with contract_version 2, exactly matching IDs, nonblank text and COMPLETE states only for finished units. Both registries declare whether they are synthetic test inputs. Do not mark actual production inputs synthetic to obtain a successful offline QA gate.
4. Map footnote occurrence IDs and anchors to unique body_unit_id values. The body must exactly match that side's checked unit text. Map table coordinates to source units and actual target-unit cell IDs. Only explicitly approved, content-identical repeated-header aliases may merge; see the contract for coverage rules.
5. Prepare [project.json's schema](../schemas/project.schema.json): version 2, source/target/PDF relative paths with SHA-256 of the final file bytes, page count and full or declared_sample scope, layer inventory, inspection rationale/PDF hash, explicit vocabulary, term rules and pollution tokens. Keep the PDF/hash references consistent. Complete fields are mandatory; an empty mapping is not a shortcut to PASS.
6. Run source-location, term and invariant checks separately using the [quickstart entries](quickstart.md). Any input edit requires refreshed file references, rechecks and new bound evidence. A workflow snapshot is not a combined terminology/translation-quality verdict.
7. A [workflow request](../schemas/workflow.schema.json) references the current project by hash and carries the appropriate record/findings/impact fields. Read [evidence bindings](../references/evidence_contract.md) and [QA policy](../references/qa_policy.md). Actual host QA is unavailable; successful synthetic binding exercises cannot substitute for it or for a human decision.

ASCII ordinary decimal support is limited. Scientific notation, compact units such as 6m, non-ASCII signs/digits and unfamiliar expressions need unresolved manual/independent review even if not emitted by the tokenizer. Do not create empty expected arrays to hide unsupported notation. Numeric order is significant.

Retain private input files, not just hash summaries, for authorized local review. Never publish those files by default. This guide does not add an automatic import/conversion capability or certify the resulting registration.
