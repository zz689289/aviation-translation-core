# Supported contract and limits

Use `schemas/project.schema.json`, `source.schema.json`, `target.schema.json`, and `workflow.schema.json` explicitly. Every CLI takes a private existing `--root`, relative `--spec` and new relative `--output`. No absolute, parent-traversing, linked or reparse paths are accepted. Every output parent must already exist. Existing outputs and input/output collisions fail; file creation uses exclusive create, not overwrite-by-rename. Interrupted writes may leave an incomplete new output; choose another new name. Concurrent hostile replacement of directory entries is outside this single-user contract.

A project locks PDF, source registry and target registry by SHA-256. Full scope requires every page; declared_sample covers only listed pages and is always labeled. Source units have page/layer/text/evidence hash and complete expected arrays for numbers, units, identifiers, symbols and markers. Target units have matching IDs, nonblank text and COMPLETE state. Source values must be derived independently of target; the fixture expectations are manually authored from the English. Target observations are computed from its text. Schema validation cannot establish real independence.

The conservative tokenizer recognizes decimal numbers, parenthesized lowercase markers and declared unit/identifier/symbol vocabulary. Recognizable omitted uppercase identifiers and common numeric units are rejected. This is not a general scientific parser: vocabulary completeness, unfamiliar notation, language-specific quantities, modality and semantic equivalence require real QA. Keep unresolved cases blocked instead of supplying fake evidence. Numbers remain order-sensitive; a permitted reordering currently needs a separately reviewed contract change.

All nine layer keys must be declared PRESENT, ABSENT or UNSUPPORTED. Present layers need mapped units; unsupported layers fail. The declaration and nonblank inspection rationale do not authenticate an actual inspection. PDF matching covers all extracted text on each selected page, not just a substring, and rejects extraction failure/empty mapping. No OCR, images, external fonts or layout construction is implemented.

Contract version 2 is required: project.version=2 and source/target.contract_version=2. Version 1 and missing version/binding fields are explicitly rejected by schema; no automatic migration is performed. Rebuild private registries from independently checked source evidence and regenerate snapshots.

Each footnote occurrence has a unique body_unit_id pointing to an actual footnotes-layer source unit and the same target unit. The retained body field must exactly equal that side's checked unit text. Anchor IDs and ordered occurrence/body bindings must agree; body references must not reuse one occurrence or refer to their own anchor. Every footnotes-layer unit must be referenced. Separate occurrences may have identical text. Source bodies participate in the PDF mapping and token checks through their units; translation meaning remains a real QA task.

Table cells are actual target unit IDs, not a separate unverified name list. Source coordinates must cover table_cells-layer units. Each coordinate maps to its matching target unit. An explicit repeated-header alias permits multiple coordinates to share one actual target unit only if all corresponding source texts/expectations and target texts agree. Missing, swapped, wrong-layer, uncovered or conflicting references fail. No layout or semantic equivalence is inferred.

Pollution tokens must be explicitly configured with at least one controlled neutral marker; no institutional identifiers are built in. Term rules use explicit forms and may overlap. Source expectations and rule strings in JSON cannot by themselves prove authoritative approval. All shared outputs remain mechanical only, human_approved=false and released=false.

R1 tokenizer scope: ASCII decimal integers and signed decimals, ASCII plus/minus signs, Chinese adjacency, spaces and sentence punctuation are supported. ASCII letters/digits/underscore protect embedded identifiers from splitting into independent numbers. Declared unit/identifier matches use ASCII identifier boundaries, so BX followed by Chinese is recognized. Numeric unit notation uses a separated unit (6 m); compact 6m, scientific notation, leading-dot decimals, non-ASCII digits/signs, thousands separators and mathematical expressions are outside this parser's numeric guarantee. Their absence from token output is NOT evidence of correctness; these cases require a blocked manual/independent review. Mechanical PASS never closes that review.

Snapshot binding version 2 hashes the entire validated project object, including term_rules, pollution_tokens, all references, vocabulary, scope, layers, inspection and contract version. Object key order is canonicalized; list order is significant. Even a path or rationale edit conservatively invalidates a binding. Input source/target schema versions are also bound through their hashes. Script/schema fingerprints remain an additional cache check. Binding reuse does not reuse semantic QA.

For the manual registration sequence, see [preparing inputs](preparing_inputs.md). No automatic importer is supplied. For executable Windows steps, see [quickstart](quickstart.md).
